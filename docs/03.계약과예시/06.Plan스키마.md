# 03.계약과예시 — Plan 스키마 (D-012)

SDD Planner가 산출하는 **실행 가능 Plan JSON** 계약이다.  
JSON Schema: [`schemas/plan.schema.json`](./schemas/plan.schema.json)

## 원칙

- Plan은 Workflow의 `required_capabilities` ↔ Skill Hub 매칭 결과다.
- `skill` + `tool` 만으로 script 경로를 해석한다 (경로 하드코딩 금지).
- Hub에 없는 skill/tool 참조는 Validator가 거부한다.
- LLM이 Plan 필드를 근거 없이 채우지 않는다. 바인딩은 Registry·script.

## 최소 예시

```json
{
  "schemaVersion": "plan/v1",
  "planId": "PLAN-001",
  "workflowId": "wf_health_smoke",
  "steps": [
    {
      "stepId": "S1",
      "agent": "platform_runner",
      "skill": "health_ping",
      "tool": "ping",
      "dependsOn": [],
      "inputs": {}
    }
  ]
}
```

## 필드

| 필드 | 설명 |
|---|---|
| `schemaVersion` | `plan/v1` |
| `planId` | 실행 단위 ID |
| `workflowId` | Workflow Hub ID |
| `steps[]` | 순서·의존 있는 실행 스텝 |
| `steps[].skill` | Skill Hub 이름 |
| `steps[].tool` | SKILL.md tools 항목 |
| `steps[].dependsOn` | 선행 stepId |
| `steps[].agent` | Named Boundary (자율 Agent 아님) |
