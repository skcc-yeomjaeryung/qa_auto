# Phase 03 — Spring Backend 의미 분석 (Python Agent / Tool)

## 이 프롬프트의 역할

당신은 대형 SI 프로젝트용 AI Code-to-E2E 관통 테스트 플랫폼의 수석 개발자다.  
프로젝트 루트에서 먼저 다음 문서를 읽고 현재 코드 상태를 점검하라.

- `docs/index.md`
- `AGENTS.md`
- `docs/01.제품과완료기준/02.공통컨텍스트.md`
- `docs/02.아키텍처/03.의사결정기록.md` (D-007 · **D-010**)
- 관련 JSON Schema와 이전 Phase 완료 보고서 (`PHASE-01`, `PHASE-02`)

계획 문서만 작성하지 말고, **실제 구현·테스트·문서화·완료 보고까지 한 번의 작업으로 수행**하라.  
모호한 부분은 기존 코드와 공통 문서를 근거로 합리적인 기본값을 채택하고, 구현을 중단하는 질문으로 돌리지 말라.

## 구현 범위

### 런타임 (플랫폼)

- `backend/workers/backend-analyzer/` — **Python 3.12** 패키지
- SDD 축소 구조 (NH_AML 참조):
  - `skills/backend_spring_analyze/SKILL.md` — capability · Tool 계약
  - `skills/.../script/*.py` — 사실 추출 Tool
  - (선택) `langgraph_runtime/` — Tool 순차 실행
  - Pydantic Structured Output (`backend-analysis/v1`)
- LangChain / LangGraph: 오케스트레이션·요약 보조. **사실 조작 금지**
- Control Plane: `POST /api/analyses/backend` → worker CLI 호출
- 결과: `artifacts/analysis/{id}/backend.json`

### 대상 Adapter (Spring)

- Spring MVC Annotation Adapter (`@RestController`, mapping, `@RequestBody` 등)
- Bean Validation Adapter (`@NotBlank`, `@Pattern`, …)
- Service interface / `@Service` 구현 연결
- `@ControllerAdvice` / `@ExceptionHandler` / HTTP Status 후보
- JUnit 5 · MockMvc · REST Assured Test Evidence 추출
- Maven/Gradle는 **메타데이터 힌트**(source root 탐지)만 — JVM Symbol Solver 필수 아님
- Java 파싱 라이브러리: **순수 Python** (예: `javalang`). 한계는 `unresolved`

## 상세 구현 요구사항

1. Phase 01 `workspacePath`만 읽는다. 분석기가 git clone을 다시 수행하지 않는다 (필요 시 sync API 재호출).
2. source root(`src/main/java`, `src/test/java`)를 탐색해 `.java`를 수집한다.
3. 다음 Annotation을 우선 지원한다.
   - `@RestController`, `@Controller`
   - `@RequestMapping`
   - `@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`, `@PatchMapping`
   - `@RequestBody`, `@RequestParam`, `@PathVariable`
   - `@Valid`, `@Validated`
4. Request DTO 필드, 타입, required, pattern, size, min/max, enum을 추출한다.
5. Response DTO 필드와 JSON name 후보를 추출한다.
6. Controller→Service 호출과 주요 조건 분기(상태/예외)를 추출한다.
7. `@ControllerAdvice`, Exception Handler, HTTP Status 후보를 추출한다.
8. JUnit/MockMvc/REST Assured에서 입력값, endpoint, status, body assertion을 추출한다.
9. Lombok, record, getter/setter는 가능한 범위에서 해석하고, 실패 시 `unresolved`.
10. Interface 구현체가 여러 개인 경우 후보와 조건을 기록한다.
11. Reflection, Profile, AOP로 확정 불가 정보는 `unresolved`로 기록한다.
12. 모든 결과에 `commitSha`, file/line, extractor, confidence를 포함한다.
13. 증분: file hash 목록을 결과에 포함한다.

## API·계약·데이터

Backend Analysis Result 최소 구조:

```json
{
  "schemaVersion": "backend-analysis/v1",
  "commitSha": "...",
  "workspacePath": "...",
  "endpoints": [],
  "requestDtos": [],
  "validations": [],
  "services": [],
  "responseDtos": [],
  "exceptions": [],
  "existingTests": [],
  "unresolved": [],
  "fileHashes": []
}
```

필수 API:

- `POST /api/analyses/backend`
  - body: `projectId`, optional `repositorySetId` / `workspacePath` / `commitSha`
  - workspace 해석: sync된 `role=backend`의 `workspacePath` → 없으면 `path`(절대경로) → 없으면 body override → 없으면 400
- `GET /api/analyses/{id}/backend/endpoints`
- `GET /api/analyses/{id}/backend/endpoints/{endpointId}`
- `GET /api/analyses/{id}/backend/unresolved`
- `GET /api/analyses/{id}/backend` (전체 결과)
