# Phase 99 — 전체 파일럿 통합·인수 시나리오 검증

## 이 프롬프트의 역할

당신은 대형 SI 프로젝트용 AI Code-to-E2E 관통 테스트 플랫폼의 수석 개발자다.  
프로젝트 루트에서 먼저 다음 문서를 읽고 현재 코드 상태를 점검하라.

- `AGENTS.md`
- `README.md`
- `index.md`
- `00_common_context.md`
- `00_pilot_definition_of_done.md`
- 관련 JSON Schema와 이전 Phase 완료 보고서

계획 문서만 작성하지 말고, **실제 구현·테스트·문서화·완료 보고까지 한 번의 작업으로 수행**하라.  
모호한 부분은 기존 코드와 공통 문서를 근거로 합리적인 기본값을 채택하고, 구현을 중단하는 질문으로 돌리지 말라.

## Phase 목표


Phase 00~15의 기능을 하나의 고객조회 A→B 데모로 통합하고, 파일럿 Definition of Done을 자동·수동 인수 체크로 검증한다.


## 선행조건


- Phase 00~15 완료
- 모든 Phase 보고서 존재
- Sample Frontend/Backend와 플랫폼 기동 가능


## 구현 범위


- end-to-end demo
- regression suite

- acceptance checklist
- demo data reset
- operator runbook


## 상세 구현 요구사항


1. 깨끗한 환경에서 전체 시스템을 기동한다.
2. Sample Frontend/Backend를 Repository로 등록한다.
3. Commit을 고정하고 Frontend/Backend 분석을 실행한다.
4. API 매핑과 Interaction Graph를 생성한다.
5. 고객조회 정상/제한/미존재/형식오류 Scenario를 생성한다.
6. Input Profile을 생성하고 승인한다.
7. 건별 정상 테스트를 실행한다.
8. Backend Request/Response와 B Binding을 검증한다.
9. Evidence ZIP을 생성하고 Manifest hash를 검증한다.
10. Batch 테스트를 정해진 횟수로 실행한다.
11. 고객 역할로 HITL 승인과 반려/재실행을 각각 수행한다.
12. 모든 상태 전이와 Audit Trail을 검증한다.
13. Secret/PII 마스킹을 수동·자동으로 확인한다.
14. 외부 인터넷 없이 재실행한다.
15. 실패 주입 테스트:
    - Backend timeout
    - response field mismatch
    - locator 변경
    - backend log 누락
    - evidence 저장 실패
16. 오류가 사용자에게 명확히 보이고 증적이 부분 보존되는지 확인한다.
17. 운영자 Runbook과 고객 Demo Script를 작성한다.


## API·계약·데이터


- `00_pilot_definition_of_done.md`의 모든 항목을 검증 매트릭스로 변환한다.
- 각 항목은 자동 테스트 ID, 수동 검증자, Evidence link, 결과를 가진다.
