# Phase 10 — Frontend Network와 Spring Backend Request·Response 추적

## 이 프롬프트의 역할

당신은 대형 SI 프로젝트용 AI Code-to-E2E 관통 테스트 플랫폼의 수석 개발자다.  
프로젝트 루트에서 먼저 다음 문서를 읽고 현재 코드 상태를 점검하라.

- `AGENTS.md`
- `README.md`
- `index.md`
- `00_common_context.md`
- `00_pilot_definition_of_done.md`
- 관련 JSON Schema와 이전 Phase 완료 보고서

계획 문서만 작성하지 말고, **실제 구현·테스트·문서화·완료 보고까지 한 번의 작업으로 수행**하라.  
모호한 부분은 기존 코드와 공통 문서를 근거로 합리적인 기본값을 채택하고, 구현을 중단하는 질문으로 돌리지 말라.

## Phase 목표


동일 Test Run ID를 사용해 **agent-browser MCP Network 관측**과 Spring Controller 진입, Request DTO, Response DTO, HTTP 상태를 하나의 관통 로그로 연결한다.


## 선행조건

## 구현 범위


- Correlation header
- Spring Filter/Interceptor
- MDC
- Structured JSON Log
- Request/Response capture
- masking
- log ingestion
- run timeline


## 상세 구현 요구사항


1. `X-Test-Run-ID`, `X-Scenario-ID`, `X-Test-Case-ID`, `X-Input-Profile-ID`를 Browser에서 주입한다.
2. Spring Filter/Interceptor가 값을 검증하고 MDC에 넣는다.
3. 다음 이벤트를 구조화한다.
   - request_received
   - validation_passed/failed
   - controller_entered
   - service_called
   - response_returned
   - exception_mapped
4. Request/Response Body는 허용된 JSON 필드만 수집하거나 마스킹한다.
5. Authorization, Cookie, Token, Password는 절대 저장하지 않는다.
6. 큰 payload는 크기 제한과 truncation metadata를 적용한다.
7. Control Plane이 Backend 로그를 수집해 Run Timeline에 병합한다.
8. 파일, HTTP ingest, OpenTelemetry 중 Pilot에 적합한 adapter를 구현하되 인터페이스를 분리한다.
9. Backend 수정이 불가능한 외부 대상에는 Browser network evidence만 사용하고 제약을 표시한다.
10. 동일 Run의 중복/재시도 Request를 sequence로 구분한다.
11. Log가 없어도 실행 Worker가 무한 대기하지 않도록 timeout과 partial evidence 상태를 둔다.


## API·계약·데이터


Structured Log 예시:

```json
{
  "timestamp": "...",
  "event": "response_returned",
  "testRunId": "RUN-001",
  "scenarioId": "customer-search-detail-001",
  "controller": "CustomerController.search",
  "request": {"customerId":"C10001"},
  "response": {"customerId":"C10001","riskLevel":"HIGH"},
  "status": 200,
  "durationMs": 42,
  "maskedFields": []
}
```

필수 API:
- `POST /api/test-telemetry/backend`
- `GET /api/runs/{id}/timeline`
- `GET /api/runs/{id}/backend-events`


## UI 요구사항


Run 상세 Timeline에 다음을 순서대로 표시한다.

- Browser input
- Frontend Request
- Backend request_received
- Controller/Service
- Backend Response
- Browser response_received
- B Binding

마스킹된 필드는 명확히 표시한다.


## 필수 테스트


- header propagation
- MDC cleanup
- request/response masking
- validation failed
- exception mapping
- duplicate request sequence
- missing backend log timeout
- payload truncation
- concurrent run isolation


## 완료 기준


- [ ] Browser Request와 Backend Log가 동일 Run ID로 연결된다.
- [ ] Backend Request DTO와 Response DTO를 확인할 수 있다.
- [ ] HTTP 상태와 처리시간이 기록된다.
- [ ] Secret/PII가 마스킹된다.
- [ ] 동시 실행 로그가 섞이지 않는다.
- [ ] 로그 누락 시 partial evidence로 명확히 표시된다.
