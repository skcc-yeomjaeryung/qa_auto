# Phase 00b — Backend SDD 기반 재구축

## 이 프롬프트의 역할

당신은 QA_AUTO Code-to-E2E 플랫폼의 수석 개발자다.  
구 `backend/` 는 **전량 폐기**되었다. NH_AML 정렬 SDD로 `backend/` 를 다시 만든다.

반드시 읽을 문서:

- `docs/index.md` · `AGENTS.md`
- `docs/02.아키텍처/05.BackendSDD구조.md`
- `docs/02.아키텍처/03.의사결정기록.md` (D-012)
- `docs/03.계약과예시/06.Plan스키마.md`

계획만 쓰지 말고 **구현·테스트·문서·완료 보고**까지 수행한다.  
NH_AML 코드를 통째로 복사하지 않는다. 디렉터리·계약·가드레일만 이식한다.

## Phase 목표

Workflow Hub + Skill Hub + `app/core` (router·planner·orchestrator·review·reduce) + LangGraph 공통 Plan 실행 엔진이 기동하고, 최소 Workflow/Skill 1쌍으로 plan→execute smoke가 통과한다.

## 선행조건

- Phase 00 이력 (frontend · sample-targets 존재)
- Python 3.12 · Node LTS
- D-012 합의 완료
- 현재 트리에 `backend/` 가 없음 (깨끗한 재구축)

## 구현 범위

1. `backend/` 패키지 스캐폴드 (`pyproject.toml`, FastAPI `main`, `/health`)
2. Hub 디렉터리 + Loader (**교보재 few-shot 포맷 강제**)
   - 작성 기준: `docs/05.템플릿/few-shot/template_workflow.yml` · `template_skill.md`
   - `workflow_definitions/` (최소 Workflow 1)
   - `skills/health_ping/` (`SKILL.md` §1~§14 + script + sample_input/output)
   - `capability_definitions/`
3. `app/core/` — router · planner · orchestrator · reviewer · reducer · registries · tool_runtime (최소 동작)
4. `langgraph_runtime/` — 공통 `plan_execution_graph` (Hub 아님)
5. Registry 교차검증 (기동 시 Hub 자산 정합)
6. Plan JSON Schema 검증 ([`../03.계약과예시/schemas/plan.schema.json`](../03.계약과예시/schemas/plan.schema.json))
7. pytest: Hub 로드 · health_ping plan→execute · `/health`
8. `Makefile` `test-backend` · `scripts/dev-up.sh` backend 기동 복원

후속 Phase에서 Skill로 재편할 것 (이번 Gate 밖):

- `frontend_analyze` · `backend_spring_analyze` · `api_map`
- `backend/workers/*` 재도입

## 상세 요구사항

1. 관리형 Hub는 Workflow + Skill만. Graph Hub / `graph_manifest` 금지.
2. Hub에 없는 Skill/Tool을 LLM·코드가 발명하지 못하게 Validator로 차단.
3. Plan의 skill+tool로만 script 경로 해석 (하드코딩 금지).
4. LLM은 요약·후보만. health_ping 사실은 script.
5. Agent는 Named Boundary thin adapter. 자율 Agent 금지.
6. Pass/Fail·배포 단정 금지. HITL·missing_data 유지.
7. `services/` 에 분석·시나리오 확정 로직을 Hub 우회로 넣지 말 것.
