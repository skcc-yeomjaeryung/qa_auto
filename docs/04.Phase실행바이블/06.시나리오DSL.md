# Phase 06 — Interaction Graph 기반 실행 가능한 Scenario DSL 생성

## 이 프롬프트의 역할

당신은 대형 SI 프로젝트용 AI Code-to-E2E 관통 테스트 플랫폼의 수석 개발자다.  
프로젝트 루트에서 먼저 다음 문서를 읽고 현재 코드 상태를 점검하라.

- `AGENTS.md`
- `README.md`
- `index.md`
- `00_common_context.md`
- `00_pilot_definition_of_done.md`
- 관련 JSON Schema와 이전 Phase 완료 보고서

계획 문서만 작성하지 말고, **실제 구현·테스트·문서화·완료 보고까지 한 번의 작업으로 수행**하라.  
모호한 부분은 기존 코드와 공통 문서를 근거로 합리적인 기본값을 채택하고, 구현을 중단하는 질문으로 돌리지 말라.

## Phase 목표


Interaction Graph에서 실제 **agent-browser MCP** 실행과 Backend/UI 검증에 사용할 Scenario DSL을 생성하고 버전·근거·미해결 항목을 관리한다.

## 상세 구현 요구사항


1. 결정론적으로 생성 가능한 다음 항목은 LLM에 맡기지 않는다.
   - Route
   - Locator 후보
   - Event type
   - HTTP method/path
   - Request/Response field mapping
   - Evidence
2. LLM은 시나리오 제목, 업무 설명, 의미 기반 assertion 후보, 고객 검증 질문을 생성한다.
3. LLM 입력은 Graph subset과 Evidence reference만 사용한다.  
   Project에 Design Spec이 있으면 annotation을 **추가 컨텍스트**로만 포함한다 (단독 확정 금지).
4. LLM 출력은 Schema 검증과 Evidence reference 검증을 거친다.
5. 불확실한 expected value는 `unresolved` 또는 `reviewRequired`로 남긴다.
6. Scenario는 source commit 조합, graph version, 생성기 version을 기록한다.
7. 변경된 Graph에서 Scenario diff를 생성한다.
8. 시나리오 상태:
   - `DRAFT`
   - `READY_FOR_INPUT`
   - `EXECUTABLE`
   - `DEPRECATED`
9. Step은 안정적 ID와 timeout/retry policy를 가진다.
10. Assertion은 hard/soft/business-review로 분리한다.
11. 생성된 DSL을 사람이 읽을 수 있는 Flow 요약과 함께 제공한다.
12. **세션 선행조건 (D-015 · 강제)** — 시나리오는 `authRequired` · `sessionPolicy`
    (`no_auth` | `login_then_reuse` | `reuse_existing_session` | `fresh_login_required`)를 갖는다.
    - 인증 뒤 화면(로그아웃·잔액·송금·거래내역·내 정보 등)은 **로그인 선행 step + 세션 확인 step**을 포함한다.
    - **로그아웃 시나리오는 예외 없이 선행 로그인을 포함한다.** 로그인 없는 로그아웃 시나리오는 생성하지 않는다.
    - 로그인 값은 연결 정보 참조만 둔다 (`environment.loginId` / `environment.loginSecret`). 값 생성 금지.
    - 로그인·로그아웃은 URL 직접 접근이 아니라 화면 입력·클릭 step으로 만든다.
    - 기대 결과는 `verdictCriteria[]` 로 **화면 관측 가능한 문장**으로 남긴다.
      「Endpoint 도달」을 기대 결과로 쓰지 않는다.
    - 근거가 없으면 `missing_data` (`graph:loginControls`, `connection.loginSecret`).
    - 계약: [`../03.계약과예시/08.세션선행조건과판정계약.md`](../03.계약과예시/08.세션선행조건과판정계약.md) ·
      프롬프트 `backend/app/prompts/scenario/session_precondition_system.md`
13. Design Spec join (있을 때만):
    - TOP.serviceOrTxnId · title로 Scenario/Screen 후보를 매칭한다.
    - CENTER 번호 + RIGHT 설명을 step/action/assertion **후보**로 연결한다.
    - Graph node와 join되지 않으면 `missing_data` / `unjoined`로 남긴다.
    - Design Spec 문구를 hard assertion expected로 승격하지 않는다 (`business-review` 또는 soft 후보만).


## API·계약·데이터

- 필수 API:

  - `POST /api/scenarios/{id}/versions`

## 필수 테스트


- 동일 Graph에서 deterministic 결과
- Graph branch별 Scenario 생성
- LLM invalid JSON
- Evidence 없는 LLM assertion 거부
- Schema violation
- Scenario version diff
- unresolved expected value
- **로그아웃 시나리오에 선행 로그인 step이 포함된다** (D-015 회귀 고정)
- **인증 뒤 화면 시나리오에 `sessionPolicy` 가 지정된다**
