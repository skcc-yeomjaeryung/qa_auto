# 스케줄링 Workflow

## 화면 목적

프로젝트·시나리오·실행 환경·기간·시간대를 고정해 업무시간 이후 반복·대량 테스트를 예약하고,
중복 실행과 데이터 변경 위험을 통제한다.

## 사용자 흐름

1. `스케줄링 등록`에서 고유 ID와 한글명을 입력한다.
2. 프로젝트와 실행할 Scenario Set/시나리오, 실행 환경을 고른다.
3. “평일 오후 10시” 같은 자연어를 Cron으로 변환하거나 직접 Cron을 입력한다.
4. 시작일·종료일·시간대와 활성 여부를 정한다.
5. 목록에서 즉시 실행, 일시중지/활성화, CSV import/export를 수행한다.

## 코드·API 매핑

| 항목 | 값 |
|---|---|
| Route | `/manage/schedules` |
| 화면 | `frontend/components/ScheduleWorkbench.tsx` |
| API | `GET/POST/PATCH /api/schedules`, `/execute`, `/cron-preview`, `/bulk-delete` |
| 저장 | SQLite KV |
| 실행 | Schedule coordinator → Run service → 등록 실행 Workflow 경로 |

이전 실행이 끝나지 않으면 같은 스케줄을 건너뛴다. 자동 스케줄은 선택한 실행환경의
`dataMutationAllowed`를 상속하므로, 테스트 전용 환경에서 한 번 허용한 업무 관통 테스트는
추가 팝업 없이 예약 실행하고 허용하지 않은 환경은 데이터 변경 단계를 차단한다.
스케줄 완료는 기술 실행 완료이며 최종 Pass/Fail은 HITL 검토에서 결정한다.
