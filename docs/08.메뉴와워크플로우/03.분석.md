# 분석 Workflow

## 화면 목적

연결 저장소의 Frontend와 Backend를 정적 분석한 결과를 목록과 소스 트리로 확인하고,
분석 결과를 A→API→B 시나리오 생성 파이프라인의 입력으로 선택한다.

## 사용자 흐름

1. 프로젝트 범위의 분석 목록에서 FE/BE 상태, 파일 처리 Progress, 변경분을 확인한다.
2. `소스 탐색`을 열어 저장소 전체 트리와 파일 내용을 역할별로 확인한다.
3. 분석 결과를 선택하고 `시나리오 초안 만들기`를 누른다.
4. Progress 팝업에서 코드·화면·API·입력·검증 생성 단계를 확인한다.
5. 완료 뒤 테스트 시나리오 메뉴로 이동한다.

## Agentic 파이프라인

```text
wf_frontend_analyze
  + wf_backend_spring_analyze
  → wf_api_map
  → wf_interaction_graph
  → wf_scenario_dsl
  → wf_component_contract
  → wf_input_recommend
```

`wf_scenario_dsl`은 Project Context 탐색 → 결정론 DSL seed → LLM/결정론 한글 narration 순서다.
Endpoint·Route·selector skeleton은 코드 Evidence에서 만들고, LLM은 의미 설명과 후보만 보강한다.

## 코드·API 매핑

| 항목 | 값 |
|---|---|
| Route | `/analysis` |
| 화면 | `frontend/components/AnalysisWorkbench.tsx` |
| 목록·트리 | `GET /api/console/analyses`, `GET /api/console/analyses/{id}/tree`, file API |
| 시나리오 생성 | `POST /api/console/generate-scenarios` |
| Pipeline | `backend/app/services/pipeline.py` |

분석 실패·미해결 항목은 숨기지 않고 `partial`, `error`, `unresolved`, `missing_data`로 남긴다.
