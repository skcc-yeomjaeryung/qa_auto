# 프로젝트 Workflow

## 화면 목적

Code-to-E2E의 실행 범위를 하나의 프로젝트로 묶고, 저장소·모델 정책·실행 환경·보조자료를 순서대로 등록한다.

## 생성 흐름

| STEP | 입력·동작 | 결과 |
|---|---|---|
| 1 | 프로젝트 이름·설명·태그 | 프로젝트와 소유자 범위 생성 |
| 2 | AI 자동 추천/역할별 고정, `auto`·`balanced`·`internal_only` 등 정책 | Agentic Core 모델 선택 정책 저장 |
| 3 | GitHub URL 또는 Local Path, branch·저장소명 | Commit pin·동기화 뒤 FE/BE 자동 분석 |
| 4 | Frontend/Backend URL, Browser, 역할·로그인 ID·Password, 데이터 변경 허용, Health path | agent-browser 실행 환경·계정·업무 데이터 변경 정책 연결 |
| 5 | 선택형 CSV/PPT/PPTX | 코드·DOM과 join할 보조 Evidence 추출·임베딩 |
| 6 | 전체 연결 확인 | 프로젝트 상세·분석 메뉴로 이동 |

## 코드·API·Workflow 매핑

| 구분 | 값 |
|---|---|
| Route | `/projects` |
| 화면 | `frontend/components/ProjectsWorkbench.tsx` |
| 프로젝트 API | `/api/projects` |
| 저장소 연결 | `POST /api/console/connect`, `/api/repository-sets/{id}/sync` |
| 자동 분석 | `POST /api/console/bulk-analyze` |
| 실행 환경 | `/api/projects/{projectId}/environments`, `/api/environments/{id}/health-check` |
| 보조자료 | `/api/projects/{projectId}/context-documents` |
| Workflow | `wf_frontend_analyze`, `wf_backend_spring_analyze`; 후속 생성에서 매핑·Graph·Scenario Workflow 연쇄 |

Password·Token은 응답·SQLite·Trace에 원문으로 남기지 않는다. PPT/CSV는 단독 확정 근거가 아니며
Graph·DOM·API와 연결된 항목만 시나리오 후보에 반영한다.

### 데이터 변경 허용 메타데이터

- 기본값은 `false`다. 조회·화면 탐색은 실행하지만 입금·등록·수정처럼 대상 데이터를 바꾸는
  단계는 건별 1회 확인 뒤에만 실행한다.
- 테스트 전용 계정과 초기화 가능한 개발환경에서 사용자가 `데이터 변경 허용`을 선택하면
  `ExecutionEnvironment.dataMutationAllowed=true`로 저장한다.
- 이 값은 개별·일괄·예약 실행의 Browser Run 정책에 자동 상속한다. 사용자가 메뉴마다 다시
  승인하도록 요구하지 않는다.
- 실행 결과에는 허용 여부뿐 아니라 정책 출처(`environment`, `one_time_confirmation`,
  `default_block`)를 남겨 제품 결함과 QA_AUTO 안전 차단을 구분한다.
