# HITL 승인 Workflow

## 화면 목적

자동 실행 결과를 사람의 최종 품질 판단에 필요한 형태로 정리한다. 현재 화면은 검토 대기 목록과
리포트·기술 검증·증적 패키지를 제공하며, 기술 완료를 자동 승인으로 바꾸지 않는다.

## 사용자 흐름

1. 프로젝트와 Scenario Set을 선택한다.
2. 서버·화면 오류 → 기대 불충족 → 누락 증적 → 정상 관측 순으로 검토한다.
3. 실행 한 건을 선택해 `증적/리포트 검토`를 연다.
4. `실행 리포트`에서 A→API→B 경로, 먼저 확인할 내용, 승인 전 체크리스트를 읽는다.
5. `기술 검증`에서 기대값과 실제 관측값, 일치·불일치·누락·담당자 확인 항목을 대조한다.
6. `증적 패키지`에서 대표 화면과 전체 단계 캡처, artifact SHA-256·마스킹·누락을 확인한다.
7. HTML 통합 리포트 또는 JSON을 다운로드해 주간보고·감사·고객 승인 증적의 입력 자료로 사용한다.

## 코드·API·Workflow 매핑

| 항목 | 값 |
|---|---|
| Route | `/hitl` |
| 화면 | `frontend/app/hitl/page.tsx`, `RunReportDrawer` |
| API | `POST/GET /api/runs/{runId}/report`, `GET /api/runs/{runId}/report/download` |
| Workflow | `wf_run_report` → `run-report/v1` 검증 → HTML/JSON 렌더링 |

리포트 Agent는 기존 관측을 정리할 뿐 새로운 판정이나 근거를 만들지 않는다. 최종 승인/반려와 Audit Trail은
사람의 업무 권한 범위이며, 화면에 실제 승인 저장 기능이 추가될 때 Phase 15 계약과 이 문서를 함께 갱신한다.
