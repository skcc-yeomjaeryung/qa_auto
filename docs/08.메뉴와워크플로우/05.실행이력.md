# 실행 이력 Workflow

## 화면 목적

테스트 시나리오에서 시작한 개별·일괄·예약 실행을 한 곳에서 조회하고, 단계별 관측·판정 근거·증적을 개발/QA가 재현 가능하게 확인한다.

## 사용자 흐름

1. 프로젝트·시나리오·기술 상태·증적 상태로 목록을 좁힌다.
2. 실행 ID 또는 `상세·증적`을 눌러 우측 drawer를 연다.
3. 요약 탭에서 기술 상태, 기대 결과 대조, 원인 분류, 후속 조치를 확인한다.
4. 단계 탭에서 입력·클릭·API·검증별 관측과 누락 원인을 확인한다.
5. 증적 탭에서 화면 캡처·DOM snapshot을 확대하고 Evidence ZIP을 내려받는다.
6. 직전 실행 대비 변경 여부를 보고 필요한 시나리오로 돌아가 재실행한다.

## 코드·API 매핑

| 항목 | 값 |
|---|---|
| Route | `/runs`, 상세 `/runs/{runId}`, 증적 뷰 `/runs?view=evidence` |
| 화면 | `RunsWorkbench`, `RunEvidenceDrawer`, `RunTraceTimeline`, `EvidencePackageViewer`, `EvidenceGallery` |
| API | `GET /api/runs`, `/api/runs/{id}`, `/steps`, `/evidence`, `/evidence/download` |
| 생성 Workflow | `wf_browser_execute` |

`WAITING_FOR_REVIEW`, `AUTO_FAILED`, `CANCELLED`는 기술 실행 상태다. 증적 존재만으로 최종 성공을 확정하지 않는다.
