# 테스트 시나리오 Workflow

## 화면 목적

AI Agent가 코드·Graph·보조 근거에서 만든 실행 가능한 테스트 초안을 업무 그룹별로 검토하고,
개별/일괄 실행과 시각적 Workflow 재처리까지 수행하는 핵심 화면이다.

## 사용자 흐름

1. `/scenarios`에서 저장소·업무 단위 Scenario Set을 고른다.
2. 좌측 업무 분류와 시나리오를 선택하면 우측 상세가 열린다.
3. `화면 구성 확인`에서 테스트 목적, 대상 화면, 선행 로그인, 확인 항목을 본다.
4. `실행 흐름`에서 navigate/fill/select/click/API/verify 단계를 순서대로 보고 실행 관측을 대조한다.
5. `예상 테스트 결과`에서 성공·실패 기준, 기술 판정 기준, 최근 관측 결과, 입력값을 확인한다.
6. `의존관계 그래프`에서 A 화면→컴포넌트→API→Backend→B 화면 연결을 시각적으로 확인한다.
7. 추천 입력으로 개별 실행하거나 그룹/선택 그룹을 일괄 실행한다.
8. Flow 노드 `재처리`로 저장된 입력과 선행 환경을 복원해 선택 단계 이후를 다시 관측한다.

## 예상 시나리오·증적·결과의 의미

- **예상 시나리오:** 코드에서 확인한 화면, 입력, 이벤트, API, Route, 바인딩을 실행 단계로 구조화한 초안이다.
- **예상 증적:** 단계별 DOM snapshot, 화면 캡처, Network, Backend trace, assertion 중 무엇을 남길지 보여준다.
- **예상 결과:** 성공·실패 기준과 기대값 후보다. 화면 도달만으로 성공 처리하지 않고 실제 관측과 대조한다.
- **최근 결과:** 기술적 `expected_met/not_met/undetermined`와 근거다. 최종 Pass/Fail은 HITL 담당자가 결정한다.

## 코드·API·Workflow 매핑

| 항목 | 값 |
|---|---|
| Route | `/scenarios?setId=…&scenarioId=…`, Graph는 `&view=graph` |
| 화면 | `ScenarioSetWorkbench`, `ScenarioDetailPanel`, `ScenarioFlowBoard`, `FlowCanvas`, `ScenarioRunConsole` |
| Scenario API | `/api/scenarios`, `/api/scenarios/{id}`, `/api/scenarios/{id}/interaction-graph` |
| 개별 실행 | `POST /api/scenarios/{id}/runs` |
| 일괄 실행 | `POST /api/console/bulk-runs`, SSE `/api/console/bulk-runs/events` |
| 재처리 | `POST /api/console/flows/{graphId}/nodes/{nodeId}/retry` |
| Workflow | `wf_scenario_dsl`, `wf_component_contract`, `wf_input_recommend`, `wf_browser_execute` |

파괴 동작은 명시적 1회 동의 없이 실행하지 않는다. 일괄/스케줄 실행은 destructive 시나리오를 기본 제외한다.
