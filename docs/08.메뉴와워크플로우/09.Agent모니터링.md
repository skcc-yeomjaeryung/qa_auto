# Agent 모니터링 Workflow

## 화면 목적

AI Agent가 어떤 Workflow를 어떤 Plan과 모델·Skill·Tool로 수행했는지 운영자가 재현 가능한 구조화 Trace로 확인한다.

## 사용자 흐름

1. 프로젝트와 상태(진행·완료·오류)로 Trace 목록을 좁힌다.
2. Workflow명과 Trace ID를 선택한다.
3. 모델 후보 점수·제외 이유·선택 결과를 확인한다.
4. Plan step의 dependency, Agent, Skill, Tool, Artifact를 순서대로 확인한다.
5. 실제 Provider 호출 완료 여부·request ID·token·duration과 결정론 fallback을 구분한다.
6. Review·Reduce 결과와 오류 원인을 확인해 재처리 또는 모델/데이터 보강 여부를 결정한다.

## 코드·API 매핑

| 항목 | 값 |
|---|---|
| Route | `/manage/agents` |
| 화면 | `frontend/components/AgentMonitorWorkbench.tsx` |
| API | `/api/agent-monitor/summary`, `/traces`, `/traces/{id}`, `/selection-preview` |
| Event store | `backend/app/core/observability/events.py` |

Trace에는 구조화 결정 근거만 저장한다. Prompt 원문, 모델 응답 원문, chain-of-thought, Secret·Password·Token·Cookie는
수집하거나 노출하지 않는다. 모델 “선택”과 “실제 호출 완료”는 반드시 다른 이벤트로 해석한다.
