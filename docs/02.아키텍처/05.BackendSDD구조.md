# 02.아키텍처 — Backend SDD 구조 (D-012)

QA_AUTO `backend/` 는 **NH_AML 정렬 Skill-Driven Development(SDD)** 를 따른다.  
제품 가치는 Code-to-E2E 관통 테스트이며, AML Agentic UX를 이식하지 않는다.

참조 패턴(복사 금지): NH_AML `backend/README.md` · absolute SDD rules.  
계약: [`../03.계약과예시/06.Plan스키마.md`](../03.계약과예시/06.Plan스키마.md)  
Phase: [`../04.Phase실행바이블/00b.BackendSDD기반.md`](../04.Phase실행바이블/00b.BackendSDD기반.md)

---

## 1. 한 줄 구조

```text
관리형 Hub  : Workflow YML + Skill(SKILL.md)  ← 업무·분석 자산
실행 Runtime: Router → Planner → Plan JSON → LangGraph → Tool script
```

Graph는 Hub가 아니다. `langgraph_runtime/` 은 Plan을 돌리는 **공통 엔진**이다.

## 2. 디렉터리 (목표)

```text
backend/
  app/
    main.py
    api/                         # HTTP (health, projects, analyses, runs, chat/execute)
    core/
      runtime/                   # 메뉴/서비스 공통 facade
      router/
      planning/                  # Plan v2 · Agent/Skill/Model 선택
      execution/                 # dependsOn 실행 · 선행 결과 전달
      quality/                   # reviewer + reducer
      models/                    # registry · health · policy selector
      context/                   # 대용량 입력 reference store
      prompts/                   # LangChain 역할 prompt catalog
      observability/             # Agent Trace · 결정 감사 로그
      catalog/                   # Named Agent 허용 Skill 경계
      workflow_registry/
      skill_registry/
      capability_registry/
      tool_runtime/
      llm/
    langgraph_runtime/           # plan_execution_graph (Hub 아님)
    workflow_definitions/        # Workflow Hub *.yml
    skills/{name}/               # Skill Hub: SKILL.md + script/
    agents/specs/ · agents/{name}/
    capability_definitions/
    schemas/
    services/                    # 비-agent CRUD (projects/repos) — Hub 우회 금지 경로와 분리
  workers/                       # Skill script가 subprocess로 호출하는 중용량 런타임
    frontend-analyzer/
    backend-analyzer/
    agent-browser-runner/
  tests/
  pyproject.toml
```

## 3. 실행 파이프라인

```text
Console / API 요청
        │
        ▼
 Router ─── 정규화 · intent/modality · 애매하면 clarify (자동 선택 금지)
        │
        ▼
 Workflow Registry ─── Hub에 등록된 Workflow만
        │
        ▼
 Planner ─── required_capabilities → Skill Registry 매칭
        │     → Plan JSON (Schema 검증)
        ▼
 Orchestrator + LangGraph (plan_execution_graph)
        │     route → plan → execute → review → reduce → response
        ▼
 Agent Adapter → ToolRuntime → skills/*/script/*.py
        │     (필요 시 workers/* CLI 호출)
        ▼
 Structured Output + artifacts/ + (HITL 재료만, Pass 단정 금지)
```

핵심 규칙:

1. Hub에 없는 Workflow/Skill/Tool은 LLM이 만들 수 없다 (Registry·Validator).
2. Plan의 `skill + tool`만으로 script 경로를 해석한다 (경로 하드코딩 금지).
3. 사실(Endpoint·기대값·매핑 확정)은 script/rule. LLM은 요약·후보만.
4. Graph Hub / `graph_manifest.yml` / Graph Registry 금지.

## 4. Hub vs Runtime vs workers

| 구분 | 경로 | 역할 |
|---|---|---|
| Workflow Hub | `workflow_definitions/` | 무엇을 해야 하는가 (capability · logical steps) |
| Skill Hub | `skills/` | 무엇을 할 수 있는가 (Tool 계약 · script) |
| Runtime | `core/` + `langgraph_runtime/` | Plan 생성·실행·review·reduce |
| workers | `backend/workers/` | Skill이 호출하는 외부 analyzer (Hub 자산 아님) |
| services | `services/` | 동기 CRUD 등. **분석·시나리오 확정 로직을 Hub 우회로 넣지 말 것** |

## 5. 권장 개발 순서

```text
① capability_definitions/ 에 capability_id
② skills/{name}/SKILL.md + script/*.py   ← 교보재 few-shot 포맷 강제
③ agents/specs/{name}.yml + thin adapter
④ workflow_definitions/{id}.yml          ← 교보재 few-shot 포맷 강제
⑤ (필요 시) intent/slot 정의
⑥ 서버 기동 → Registry 교차검증 → pytest · smoke
```

**작성 포맷 SSOT (교보재):** [`../05.템플릿/few-shot/`](../05.템플릿/few-shot/)

- Skill: `template_skill.md` — frontmatter + 본문 §1~§14 · `tools[].script/input/output/order`

## 8. 단일 Agentic Core 구현 (D-016 · 2026-08-06)

`corev2`를 병행하지 않는다. 기존 Core를 책임별 package로 재편하고, 예전 planner/orchestrator/
reviewer/reducer wrapper와 import는 2026-08-07 완전 제거했다.

```text
AgentRuntime
  → LangGraph route
  → Planner
      Workflow capability
      → Agent 허용 Skill 검증
      → Skill priority 선택
      → Model hard filter + policy score
      → plan/v2
  → Orchestrator
      Context reference resolve
      → dependsOn output merge
      → ToolRuntime(selected endpoint/model)
  → Reviewer(Evidence/Schema)
  → Reducer(Artifact 중심 축약)
  → Response + Agent Trace
```

### 8.1 메뉴별 공통 계약

- 프로젝트는 원시 모델 ID가 아니라 AI 실행 정책을 저장한다.
- Workflow/Skill/Tool은 Hub 등록 자산만 사용할 수 있다.
- 모델 요구사항은 Skill frontmatter에 capability, context, structured output, tool calling, 품질 profile로 선언한다.
- Core가 만든 모델 선택은 Tool subprocess의 `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`, `LLM_ENABLED`에 반영된다.
- 대용량 입력은 Context Store에 한 번 저장하고 Plan에는 `contextRef`만 복제한다.
- Agent 모니터링은 Trace 단위로 후보 평가, 제외 이유, 선택 결과, Plan, 실행, Review, Reduce를 보여준다.

### 8.2 모델 정책

| 정책 | 선택 기준 |
|---|---|
| `auto` | capability·상태를 통과한 후보를 기본 가중치로 자동 선택 |
| `cost_saver` | 비용 효율 비중을 높이고 sLLM/내부 모델 활용 기회 확대 |
| `balanced` | 품질·신뢰도·속도·비용 균형 |
| `highest_quality` | 복잡한 분석·시나리오·Evidence 검토에서 품질 비중 우선 |
| `internal_only` | 외부 배포 모델을 후보에서 강제 제외 |

하드 필터를 Prompt 판단에 맡기지 않는다. 비활성, capability/context 부족, structured/tool 미지원,
health down, 내부망 정책 위반은 결정론 코드가 먼저 제외한다. 역할 Prompt는 허용 후보 비교의 설명 계약이며
Core의 최종 선택은 점수와 tie-break까지 재현 가능해야 한다.

### 8.3 프롬프트·감사 경계

- 시스템 프롬프트 SSOT: `backend/app/prompts/`
- Loader: LangChain `PromptCatalog` (`ChatPromptTemplate`, version, SHA-256)
- 저장: 후보 점수·제외 사유·선택 결과·Plan·도구 상태·Artifact·Review·Reduce
- 미저장: chain-of-thought, Secret, Password, Token, Authorization, Cookie
- 모델 profile: SQLite 저장
- API key 원문: 운영체제 Keychain 저장, API·Trace·SQLite 미노출
- 테스트 또는 `QA_AUTO_MODEL_SECRET_STORE=memory` 명시 시에만 메모리 fallback

### 8.4 서비스 구현 경계

- `PlatformRunnerAdapter → AgentRuntime`이 메뉴·서비스의 유일한 Agentic 실행 진입점이다.
- 분석·매핑·Graph·시나리오·입력 추천·브라우저 실행·리포트 생성은 등록 Workflow를 경유한다.
- `services/`는 CRUD·카탈로그·오케스트레이션 조립을 담당할 수 있지만 모델 선택이나 Skill script를 직접 우회 호출하지 않는다.
- 모델이 선택되었다는 이벤트와 Provider 호출 완료 영수증을 구분한다. 사용량 집계는 완료 영수증 기준이다.
- 메뉴별 Workflow 매핑은 [`../08.메뉴와워크플로우/index.md`](../08.메뉴와워크플로우/index.md)를 따른다.
