## D-016 상세 — 단일 Agentic Core · 모델 결정 · 관측

- **단일 Core:** `corev2`를 만들지 않는다. `runtime`, `planning`, `execution`, `quality`, `models`,
  `context`, `prompts`, `observability`, `catalog`로 책임을 분리한다.
- **완전 통합:** 구 `planner`, `orchestrator`, `reviewer`, `reducer` wrapper와 import를 제거했다.
  공식 경로는 `planning`, `execution`, `quality`이며 외부 실행 facade는 `AgentRuntime` 하나다.
- **공통 실행:** 메뉴/서비스는 `AgentRuntime`을 통해
  `route → plan → execute → review → reduce → response` LangGraph를 사용한다.
- **Plan v2:** Workflow capability별로 Named Agent 허용 범위 안의 활성 Skill과 Tool을 선택하고
  `dependsOn`, 선택 이유, 모델 결정을 Schema 검증한 Plan에 기록한다.
- **모델 등록:** OpenAI-compatible endpoint, `/v1/models`, 모델 ID, 배포 위치, capability, context,
  structured/tool 지원, 품질·신뢰도·속도·비용 점수, health를 SQLite profile로 관리한다.
  모델 profile은 SQLite에 저장한다. API Key 원문은 운영체제 Keychain에 저장하며 SQLite·API 응답·Trace에는 노출하지 않는다.
- **모델 결정:** capability/context/structured/tool/health/내부망 정책을 하드 필터로 적용한 뒤
  프로젝트의 `auto`, `cost_saver`, `balanced`, `highest_quality`, `internal_only` 가중 정책으로 정렬한다.
  선택 결과는 실제 Tool subprocess의 LLM endpoint/model 환경에 주입한다.
- **Context:** 큰 입력은 Core Context Store에 한 번 저장하고 Plan step은 참조를 전달한다.
  선행 step의 필요한 Artifact/결과만 후속 step에 합친다.
- **Prompt SSOT:** 역할 시스템 프롬프트는 `backend/app/prompts/`에 두고 LangChain
  `PromptCatalog`로 로드한다. 프롬프트 버전과 SHA-256을 결정/Review/Reduce 메타데이터에 연결한다.
- **관측:** Agent Trace는 후보 점수·제외 사유·선택 결과·Plan·Skill/Tool 상태·Artifact·Review·Reduce를
  기록한다. 모델 선택과 Provider 실제 호출 완료 영수증을 분리하고, 모델의 비공개 사고과정(chain-of-thought)은 수집하거나 노출하지 않는다.
- **HITL:** Reviewer는 구조·Evidence 계약만 검사하며 최종 Pass/Fail·배포 승인은 확정하지 않는다.
- 상세 구조: [`05.BackendSDD구조.md`](./05.BackendSDD구조.md) §8 ·
  Core 경계: [`../../backend/app/core/README.md`](../../backend/app/core/README.md)

## D-015 상세 — 세션 선행조건 · 기대 결과 판정

**배경(관측된 결함):** 로그인 없이 `/logout` 경로만 열어 실행했고, 서버가 요청을 거부(Allowlist methods)해
로그아웃은 수행되지 않았는데 "Endpoint 접근"만으로 성공 플래그와 증적이 남았다.

- **선행조건:** 시나리오는 `authRequired` · `sessionPolicy`
  (`no_auth` | `login_then_reuse` | `reuse_existing_session` | `fresh_login_required`)를 갖는다.
  인증 뒤 화면은 선행 로그인 step + 세션 확인 step(`blocking`)을 포함한다.
  **로그아웃 시나리오는 예외 없이 선행 로그인 포함.**
- **계정:** 연결 정보에 등록된 값만 참조(`environment.loginId` / `environment.loginSecret`).
  값 생성·저장·로그 금지. 세션은 실제 사용자 이벤트로만 만들고 쿠키 위조 금지.
- **판정:** Run에 `verdict`(`expected_met`|`expected_not_met`|`undetermined`) · `verdictReason` ·
  `criteriaResults[]` · `blockingIssues[]` · `coverageNote` 를 남긴다.
  도달·무예외·스크린샷 존재는 성공 근거가 아니다. 401·403·405·Allowlist·세션 미생성은 실패 신호.
- **해결 방식:** 코드 하드코딩이 아니라 **시스템 프롬프트 + SKILL 계약 + Phase 지침**으로 강제한다.
  - `backend/app/prompts/scenario/session_precondition_system.md`
  - `backend/app/prompts/run/verify_expected_result_system.md`
  - `backend/app/prompts/run/summarize_run_system.md` · `bind_dom_inputs_system.md` ·
    `scenario/narrate_bind_system.md`
  - `backend/app/skills/scenario_dsl/SKILL.md` · `backend/app/skills/browser_execute/SKILL.md`
- **HITL 유지:** `verdict` 는 기술 판정이며 Pass/Fail·배포 확정은 사람이 한다 (D-004 · D-009).
- 관련: [`../03.계약과예시/08.세션선행조건과판정계약.md`](../03.계약과예시/08.세션선행조건과판정계약.md) ·
  [`../04.Phase실행바이블/09.브라우저실행.md`](../04.Phase실행바이블/09.브라우저실행.md) §D·§E

## D-014 상세 — 에이전틱 시나리오 초안 (LLM + agent-browser)

- **경로:** Interaction Graph(결정론) → Scenario DSL seed(script) → LLM narrate/bind Skill(Structured Output) → ScenarioSummary 저장
- **LLM 허용:** 한글 제목·단계 서술·request/response/bindings **후보** (Evidence ID 참조 필수)
- **LLM 금지:** Pass/Fail·배포 확정 · 근거 없는 Endpoint/기대값 발명 · Hub 미등록 Workflow/Skill/Tool 발명
- **agent-browser:** 실행 시 DOM snapshot·스크린샷 Evidence (입력 직후·결과 화면 최소 2장). Console 증적 뷰로 신뢰 재료 제공
- **결정론 유지:** Graph 조성·DSL step skeleton(method/path/locator)·집계는 script/rule
- **Workflow:** `wf_scenario_dsl` logical steps에 `narrate_and_bind` 포함
