## 1. 결론

메뉴 목록의 테이블 동작을 `CommonDataTable` 하나로 통합했다. 번호, 정렬 가능한 헤더, 등록/수정 일시, 10건 페이징, 선택 체크박스와 프로세스 열은 공통 컴포넌트만 관리하며 화면별 열 폭·페이징·수직 스크롤 속성은 두지 않는다.

프로젝트 생성은 실제 브라우저에서 STEP 1~5 전체를 완료했고, 생성 후 이름 수정과 수정 일시 갱신을 확인했다. FLOW는 그래프와 단계 I/O가 각각 수직 스크롤을 만드는 구조를 제거하고 CENTER만 수직 스크롤을 소유하도록 변경했다. 노드 선택 직후 하단 inspector와 저장 CTA가 보이는 위치로 이동한다.

## 2. 공통 테이블 계약

적용 화면은 프로젝트, 분석, 테스트 시나리오 그룹, 실행 이력, HITL, 증적, 스케줄링, 모델 관리, Agent 모니터링이다.

| 항목 | 동작 |
|---|---|
| 번호 | 정렬·페이지 기준 1부터 연속 표시, 2페이지는 11부터 시작 |
| 정렬 | `sortValue`가 있는 모든 헤더 클릭 시 오름/내림차순 전환, `aria-sort` 반영 |
| 시간 | 공통 `등록/수정 일시` 열에서 `yyyy-mm-dd hh:mm:ss` 표시 |
| 페이징 | 10건 초과 시에만 10건 단위 페이지 탐색 표시 |
| 선택 | 현재 필터 전체 선택·행 선택을 공통 처리 |
| 레이아웃 | 셀 내용 줄바꿈, 수평 overflow만 table wrapper가 처리, 수직 scroll은 CENTER가 처리 |

시나리오 그룹의 `최근 실행`은 날짜 숫자값으로 정렬한다. 실제 데이터에서 내림차순 첫 행이 `2026-08-07 10:13:37`로 이동하는 것을 확인했다.

## 3. 프로젝트 기능·시간 계약

- 점검 프로젝트 `PRJ-453cf7c5bcb9`를 생성했다.
- STEP 1 이름/설명/태그 → STEP 2 GitHub 저장소 연결·자동 분석 → STEP 3 실행 환경 등록·Health Check → STEP 4 보강 자료 선택 → STEP 5 최종 확인을 완료했다.
- 프로젝트 이름을 `UI UX 공통화 점검 20260807 수정완료`로 수정해 목록 반영을 확인했다.
- Project 모델에 `updatedAt`을 추가하고 생성·프로젝트 수정·저장소 연결/해제·journey 변경 때 갱신하도록 했다.
- 브라우저 목록에서 등록 `2026-08-07 10:52:27`, 수정 `2026-08-07 11:03:25`를 확인했다.
- 기존 데이터에 수정 시각이 없으면 최초 상태의 수정 시각을 등록 시각으로 표시한다. 이후 실제 수정부터 API `updatedAt`을 사용한다.
- wizard 본문은 `justify-content:flex-start`와 footer 고려 scroll padding을 사용해 큰 폼의 상단이 잘리지 않게 했다.

## 4. FLOW 스크롤·포커스

- `.flow-page .page-shell-center`가 유일한 수직 scroll owner다.
- graph viewport의 높이 제한과 수직 overflow를 제거하고 필요한 경우 수평 이동만 허용했다.
- inspector의 `42vh` 높이 제한, grid/pane 내부 수직 overflow를 제거했다.
- 입력·출력 JSON은 내용 높이에 맞춰 확장되고 가로 내용은 줄바꿈한다.
- React render 이후 선택된 inspector에 `scrollIntoView(block: start)`와 focus를 적용했다.
- 그래프는 focus 가능하며 좌우 방향키, Home, End로 수평 이동할 수 있다.
- 실제 62-node FLOW에서 Backend 노드를 선택한 뒤 Query/Variables/Response와 `이 단계 값 저장`, 하단 `새 연결 추가`·`상태 새로고침`이 같은 CENTER 흐름 안에 노출되는 것을 확인했다.
