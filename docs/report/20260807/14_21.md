# 14_21 — Qwen 실호출 증명·모델 사용량 관측·팝업 공통화

- 날짜: 2026-08-07
- Phase: 14.배치테스트
- 회차: 21
- 작업자/Agent: Codex
- 기준 포인터: `docs/index.md` 현재 Phase 14

## 1. 결론

사용자가 지적한 의심은 맞았다. 기존 `PLAN-2c09301d1ce5`와 시나리오 생성 Trace는 Qwen을 **선택**한 기록만 있었고 실제 Provider 호출 영수증은 없었다. 저장된 21개 시나리오도 `narrationMode=deterministic`이었다.

원인은 Tool subprocess를 Backend 가상환경이 아닌 시스템 `python3`로 실행한 것이었다. `scenario_narrate`가 `pydantic`을 import하지 못했지만 광범위 예외 처리로 이를 숨기고 결정론 fallback을 반환했다. 따라서 Workflow는 0.5초 만에 완료되고 GPU 사용량도 발생하지 않았다.

## 2. 모델 실행 경로 수정

| 영역 | 적용 계약 |
|---|---|
| Python 실행 | Tool subprocess는 문자열 `python3`가 아니라 Backend의 `sys.executable` 사용 |
| 대량 narration | 최대 40건 일괄 요청 대신 3건 단위 호출, 2K output truncation 방지 |
| 부분 성공 | 성공 시나리오는 `llm`, 미응답 시나리오는 `deterministic`, 전체는 `llm_partial` 가능 |
| 호출 영수증 | request ID·Provider response ID·model·operation·duration·prompt/completion/total token만 기록 |
| 비밀값 | prompt·response·API key·계정 값은 영수증과 Trace에 저장하지 않음 |
| 선택/사용 분리 | `model_selected`와 `model_invocation_completed/failed/model_not_invoked`를 별도 Event로 저장 |

## 3. 모니터링

- Trace 요약에 `modelExecutionStatus`, `modelCallCount`, `modelTotalTokens`를 추가했다.
- 기존 Trace는 실호출 증거가 없으므로 `과거 로그 · 확인 불가`로 표시한다.
- 신규 Trace는 `실제 호출 확인`, `응답 미사용`, `호출 안 함`을 구분한다.
- 상세 drawer에 Provider 응답 ID·처리 시간·입출력 토큰을 `모델 호출 영수증`으로 표시한다.
- Prometheus `/metrics`를 추가했다.
  - `qa_auto_model_invocations_total`
  - `qa_auto_model_tokens_total`
  - `qa_auto_model_invocation_duration_milliseconds_sum`
  - `qa_auto_model_selected_without_invocation`

## 4. 통제된 Qwen 실호출 증적

저장 시나리오를 변경하지 않는 1건짜리 검증 Plan을 실제 Orchestrator 경로로 실행했다.

| 항목 | 값 |
|---|---|
| Trace | `PLAN-QWEN-VERIFY-034803` |
| 모델 | `기본 로컬 모델 · Qwen 3.6 27B` / `Qwen3.6-27B-FP8` |
| 생성 방식 | `llm` |
| Provider response | `chatcmpl-a48d7bbbdfeb8499` |
| 처리 시간 | 6,877ms |
| 입력/출력/전체 | 2,887 / 620 / 3,507 token |
| API 요약 | `modelExecutionStatus=used`, `modelCallCount=1`, `modelTotalTokens=3507` |
| Metrics | completed 1 · prompt 2887 · completion 620 · total 3507 |

기존 `PLAN-2c09301d1ce5`는 신규 계약에서 `unverified`로 표시된다. 과거 로그에 호출 영수증이 없으므로 소급해 사용했다고 단정하지 않는다.

## 5. Figma 공통 컴포넌트·문구·스크롤

- 시나리오 생성 팝업은 딱딱한 영문 업무 라벨을 제거하고 `코드 근거로 자동 만들기` / `내 테스트 데이터 불러오기`로 정리했다.
- AI라는 단어만으로 실사용을 암시하지 않고 완료 후 Agent 모니터링에서 실제 호출 여부를 확인하도록 안내한다.
- 계정 팝업의 raw input을 Figma 매핑 공통 `InputField`, 버튼을 공통 `Button`으로 교체했다.
- 실행 결과 안내 CTA는 공통 `ButtonLink`를 추가해 `실행 결과 열기`로 단순화했다.
- 계정 팝업은 실제 CENTER 높이 기준으로 제한하고 고정 header/footer + 단일 시나리오 목록 scroll로 바꿨다.
- 1280px Agent drawer가 LEFT 메뉴 뒤로 들어가던 폭 계산을 수정했다.
- 제목·설명·Trace 타임라인의 지나치게 작은 글자를 키우고, 부드러운 안내형 문장으로 변경했다.
