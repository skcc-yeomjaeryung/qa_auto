## 1. 결론

HITL 승인 화면이 실행 이력 상세 슬라이드를 재사용하던 구조를 제거하고, 실행 이력·시나리오·기술 검증·Evidence Package를 고정 `run-report/v1` 계약으로 묶는 `REPORT AGENT`를 도입했다.

교보재에서는 `Workflow → Capability → Skill → 입력 검증 → 결정적 HTML 렌더링 → Reviewer` 구조만 가져왔다. 거래패턴·자금흐름·의심거래 등 AML 입력과 판단은 일절 사용하지 않았다.

## 2. 구현

| 영역 | 적용 내용 |
|---|---|
| Workflow Hub | `wf_run_report` · `QA.RUN.REPORT_GENERATE` · `run_report/generate_run_report` |
| Structured Output | `run-report/v1` JSON Schema + Pydantic `extra=forbid` 이중 검증 |
| 입력 SSOT | RunSummary · ScenarioSummary · BindingValidationResult · EvidenceManifest |
| 누락 정책 | 근거 없는 값은 생성하지 않고 `missing_data`와 담당자 확인 항목으로 표시 |
| 최종 판정 | 항상 `PENDING_HUMAN_REVIEW`; REPORT AGENT가 Pass/Fail·승인을 결정하지 않음 |
| 보안 | 입력값·Secret을 리포트 source/output에 포함하지 않고 owner 기반 API 권한 확인 |
| 보관 | `artifacts/reports/runs/{runId}/report.json`, `report.html` |
| API | 생성/재생성 · 조회 · HTML/JSON 다운로드 |
| HITL UI | `실행 리포트` · `기술 검증` · `증적 패키지` 3탭 전용 drawer |
| 목록 CTA | 행/하단 버튼을 `증적/리포트 검토`로 변경 |

## 7. 다음 전달사항

- 리포트는 실행 원본에서 파생되는 artifact이므로 실행·바인딩·Evidence가 바뀌면 `force:true`로 재생성한다.
- 기술 검증 항목이 0건이어도 원본 상태를 임의 보정하지 않고 0건 그대로 보여준다. 계약 보강이 필요하면 BindingValidation source부터 수정한다.
- Evidence `partial`은 숨기지 않는다. 담당자가 누락 근거와 패키지 무결성을 확인한 뒤 승인한다.
- Phase 포인터는 사용자 화면별 수용 검증이 계속되는 동안 14로 유지한다.
