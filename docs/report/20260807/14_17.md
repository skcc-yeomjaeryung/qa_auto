# 14_17 — 관리 화면 공통 헤더 정렬 복구

- 날짜: 2026-08-07
- Phase: 14.배치테스트
- 회차: 17
- 작업자/Agent: Codex
- 기준 포인터: `docs/index.md` 현재 Phase 14

## 1. 이번 단계에서 한 일

1. 사용자 제공 화면을 기준으로 모델 관리 화면의 상단 여백·제목 크기·검색창 정렬이 다른 목록 화면과 다른 원인을 확인했다.
2. 모델 관리 헤더가 정의되지 않은 `workspace-page-head`와 `h1`을 사용하던 부분을 공통 `content-header`·`h2` 구조로 변경했다.
3. 설명 문구에 공통 `muted` 스타일과 동일한 상단 간격을 적용했다.
4. 같은 헤더 구조를 공유해 동일 결함이 발생하던 Agent 모니터링 화면도 함께 정렬했다.
5. 기존 `PageShell`의 header/center 스크롤 계약과 테이블·검색 기능은 변경하지 않았다.
6. 로컬 Console에서 모델 관리와 Agent 모니터링을 열어 공통 헤더 구조, 검색창 우측 정렬, 가로 넘침, Console 오류를 관측했다.

## 3. 실행·검증

- `frontend/`에서 `npm run build`를 실행했다.
- Next.js production build는 compile, type check, 정적 페이지 생성, build trace 수집까지 완료됐다.
- 로컬 `http://127.0.0.1:3000/manage/models` 화면 DOM에서 제목이 `h2`, 내부 헤더가 `content-header`인 것을 확인했다.
- 1280×720 기본 viewport에서 모델 관리 헤더는 폭 1022px·높이 111.75px, 검색 영역은 우측 x=997px에 정렬됐다.
- 문서와 body의 scroll width가 viewport와 같은 1280px로 관측돼 화면 단위 가로 넘침은 없었다.
- Agent 모니터링도 같은 폭·높이·검색 정렬을 사용했고, 두 화면의 Console error는 0건으로 관측됐다.
- 기술 구현·관측 결과이며 최종 화면 수용 판단은 사용자에게 남는다.

## 4. 다음 단계

- 모델 관리와 Agent 모니터링의 관리 기능·테이블 계약은 기존 상태를 유지한다.
- 추가 화면별 수용 피드백이 있으면 같은 `PageShell → content-header` 구조를 기준으로 조정한다.
- Phase 포인터는 14.배치테스트로 유지한다.
