## 1. 결론

프로젝트 상세의 중복 설명과 큰 카드 여백을 제거해 프로젝트 정보·연결 저장소·실행 환경이 1280×720 CENTER 한 화면에 들어오도록 압축했다. 프로젝트 수정은 5개 STEP을 직접 눌러 필요한 구간만 편집하며, 저장소 STEP은 기존 연결을 제자리에서 갱신한다.

실행 이력의 개별 시나리오/customerId 입력은 제거했고, 분석 목록은 내부 분석 ID 대신 `{프로젝트명} 분석 그룹`을 노출한다. 공통 목록은 등록/수정일시의 전체 timestamp를 기준으로 최신순을 기본 적용한다.

## 2. 프로젝트 상세·수정

| 영역 | 적용 계약 |
|---|---|
| 상세 제목 | `{프로젝트명} › 프로젝트 상세`의 작은 인라인 제목 |
| 안내 | `입력·연결 결과와 후속 프로세스를 한눈에 확인합니다.`만 유지 |
| 내부 ID | `PRJ-… · 등록·연결 상태` 문구와 저장소/환경 내부 ID 제거 |
| 밀도 | 둥근 카드의 중첩·그림자·과도한 여백 제거, 연결된 정보 구획으로 압축 |
| 핵심 정보 | 프로젝트 정보·연결 저장소·실행 환경을 footer 위에 우선 노출 |
| STEP 수정 | 프로젝트 이름/저장소/실행 환경/보강 자료/최종 확인 5개 STEP 직접 이동 |
| 기존 값 | 이름·설명·태그·정책·저장소 URL/path·환경 값 사전 입력, Secret은 재노출하지 않음 |
| 저장소 수정 | `repositorySetId`를 전달해 기존 연결 source/name을 제자리 갱신 후 sync·분석 |

## 3. 저장소 중복 방지

- 동일 GitHub URL 또는 로컬 경로는 표시명이 달라도 같은 연결 identity로 판단한다.
- 같은 원본을 다시 연결하면 기존 repository set을 재사용한다.
- 수정 STEP에서 원본 경로가 바뀌어도 같은 repository set을 갱신하므로 연결 수가 증가하지 않는다.
- 과거에 이미 생긴 중복 set은 분석/시나리오 참조를 깨지 않도록 물리 삭제하지 않고, 프로젝트 화면에서는 원본 기준 한 연결로 통합 표시한다.

## 4. 실행 이력·분석 목록

| 화면 | 변경 |
|---|---|
| 실행 이력 | 개별 시나리오 select·customerId 입력·화면 내 실행 CTA 제거 |
| 실행 시작 위치 | 테스트 시나리오 상세로 단일화, footer는 `테스트 시나리오 보기` 제공 |
| 조회 범위 | 프로젝트·테스트 시나리오 그룹 범위만 유지 |
| 분석 목록 | `분석 그룹 ID` → `분석 그룹`, 화면에는 `{프로젝트명} 분석 그룹` 표시 |
| 내부 식별자 | 분석 원시 ID는 API/상세 참조용으로만 유지 |

## 5. 공통 최신순 계약

- `CommonDataTable` 초기 정렬은 항상 `등록/수정 일시 · 내림차순`이다.
- 정렬값은 날짜 문자열이 아니라 전체 timestamp의 epoch millisecond를 사용한다.
- 같은 년월일도 시·분·초까지 비교해 최신 데이터가 위에 온다.
- Backend in-memory 목록도 DB의 `ORDER BY COALESCE(updated_at, created_at) DESC`와 같은 의미로 프로젝트·환경·분석·매핑·그래프·시나리오·실행·배치를 최신순 반환한다.
