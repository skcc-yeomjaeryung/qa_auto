# 14_25 — 최고 품질 모델 시나리오 생성 복구·대시보드 검토 동선 보정

- Phase: 14.배치테스트
- 회차: 25
- 작업자/Agent: Codex
- 기준 포인터: `docs/index.md` 현재 Phase 14

## 1. 결론

`highest_quality` 프로젝트의 시나리오 생성이 기본 Qwen을 사용하거나 180초에 종료되던 문제를 모델 선택 시점, 실제 provider 호출, 후처리 저장 구간으로 분리해 확인했다. OpenAI 프로필이 정상 상태인 현재는 GPT-5가 선택되고, 제한 시간 안에 유효한 응답을 부분 반영한 뒤 21개 시나리오를 저장한다.

대시보드 `결과 검토`는 빨간 경고가 항상 붙던 표현을 제거했다. 실제 HITL 대기 건수가 있을 때만 보라색 강조와 건수를 표시하고, 클릭하면 `/hitl`로 이동한다.

## 2. 원인

| 구간 | 원인 |
|---|---|
| 과거 Qwen 선택 | 당시 OpenAI 프로필/Health가 후보에 없어서 자동 추천 가능 후보가 내부 모델뿐이었음 |
| 생성 중단 | 40개까지 3건씩 최대 90초 호출하면서 전체 Skill subprocess 제한은 180초여서 정상 처리도 강제 종료될 수 있었음 |
| GPT-5 응답 미반영 | 2,048 completion token으로 JSON이 잘리거나 요청별 40초 제한에 걸렸음 |
| 숨은 Qwen 호출 | Agent workflow 이후 중복 제거·업무 분류가 프로젝트 라우팅을 거치지 않는 전역 기본 LLM을 다시 호출했음 |
| 시나리오 증가 | 재생성 graph가 바뀔 때 같은 project/case도 새 row로 누적됐음 |
| 결과 검토 빨간불 | 대기 건수와 무관하게 `is-review` 경고 class를 항상 사용했음 |

## 3. 구현

### 3.1 모델 선택·실행

- 분석 화면이 생성 전에 `/api/agent-monitor/selection-preview`를 조회한다.
- 진행 팝업에 실제 선택 모델과 선택 사유를 표시한다.
- GPT-5 narration은 1건 단위, `reasoning_effort=minimal`, 최대 8,192 completion token을 사용한다.
- 전체 LLM 구간은 140초 budget을 지키며, 남은 항목은 코드·Graph 근거 기반 규칙으로 보완한다.
- provider 성공/실패 영수증과 `llm_partial` 출처를 Agent Trace에 남긴다.
- 프로젝트 라우팅 밖의 후처리 LLM 호출을 제거해 선택 모델과 실제 호출 모델이 어긋나지 않게 했다.

### 3.2 저장·목록

- 같은 `projectId + caseId` 재생성은 최신 시나리오 row를 갱신한다.
- 기존 history는 내부 ID 조회 가능 상태로 보존하되 목록은 project/case별 최신 1건만 표시한다.
- 서버가 일부 결과 또는 오류 메시지를 반환하면 진행 팝업이 이를 그대로 설명한다.

### 3.3 대시보드·동선

- `결과 검토`는 `reviewCount > 0`일 때만 강조한다.
- 강조색은 오류를 뜻하는 빨강 대신 서비스의 보라색 톤으로 통일했다.
- 접근성 이름은 `결과 검토 N건` 또는 `검토 대기 없음`으로 데이터에 연동된다.
- 실제 브라우저에서 분석 → 테스트 시나리오 → 실행 이력 → HITL 승인 → 스케줄링 → 모델 관리 메뉴와 대상 화면을 확인했다.

## 6. 운영 주의

- 외부 API Key는 보안 정책상 SQLite에 저장하지 않고 현재 서버 메모리에만 둔다. 서버를 재시작하면 모델 관리에서 Key를 다시 입력하고 Health Check를 수행해야 한다.
- 완료는 기술 생성 상태다. 실행 결과의 최종 Pass/Fail은 계속 HITL 담당자가 확정한다.
- Phase 포인터는 사용자 화면별 수용 검증이 계속되는 동안 14로 유지한다.
