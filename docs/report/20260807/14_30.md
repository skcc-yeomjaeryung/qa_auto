## 2. 이번 단계에서 한 일

- 테스트 시나리오 좌측 목록의 제목 영역을 `Ctrl+왼쪽 클릭`하면 실제 `scenarioId`를 클립보드에 복사하도록 했다.
- macOS의 `Ctrl+클릭`이 context-menu 이벤트로 전달되는 경우도 같은 복사 동작으로 처리했다.
- 복사 성공 시 실행 이력에서 검색할 수 있다는 완료 안내를 표시한다.
- 실행 이력의 테스트 시나리오 ID를 실행 ID와 같은 연한 파란색 링크 스타일로 표시하고, 원본 시나리오로 이동할 수 있게 했다.
- 실행 이력 검색 기준에 전체 필드·테스트 시나리오 그룹·테스트 시나리오 ID·시나리오 한글명·실행 ID·상태·요약·결과 변경을 제공했다.
- 검색은 선택한 필드에서 영문 대소문자를 구분하지 않는 부분 일치로 동작한다.
- 실행 상세의 AI 관측 요약을 `무슨 문제가 있었나요?` → `왜 이런 오류가 발생했나요?` → `어떻게 해결하나요?` 3단계로 재구성했다.
- `submit_blocked_destructive`를 사용자용 원인 `실행 정책으로 제출 차단`으로 분류하고, 서비스 장애가 아니라 명시적 1회 승인 누락임을 설명한다.
- 과거 실행에 저장된 포괄적 진단도 조회 시 불변 실행 증적에서 다시 계산해 동일한 트러블슈팅 안내를 제공한다.

## 5. 수용 계약

- 자동 실행 차단과 대상 서비스 오류를 같은 실패 원인으로 설명하지 않는다.
- 데이터 변경 시나리오는 배치에서 기본 제외하고, 건별 실행에서 사용자의 명시적 1회 승인 후 검증한다.
- 시나리오 ID는 목록에서 복사해 실행 이력의 전용 검색 기준으로 찾을 수 있어야 한다.
- 실행 이력 검색은 영문 대소문자를 구분하지 않는 부분 일치다.
- 업무 오류·실패 기준 관측에는 문제·원인·해결 방법을 모두 제공하되, 최종 Pass/Fail은 HITL 담당자가 확정한다.
