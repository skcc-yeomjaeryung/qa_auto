## 1. 이번 단계에서 한 일

- 앱 전체에서 사용할 수 있는 대량·장시간 작업 토스트 이벤트와 단일 알림 호스트를 추가했다.
- 같은 작업 ID를 다시 알리면 별도 토스트를 쌓지 않고 시작 → 완료/실패 상태를 같은 자리에서 갱신한다.
- 토스트는 최대 3개까지만 표시하고 자동으로 사라지며 사용자가 직접 닫을 수도 있다.
- 진행·완료·실패·안내 톤을 분리하고 `aria-live`·`status`·`alert` 역할을 적용했다.
- 모든 공통 테이블의 CSV 내보내기·가져오기가 `TableBulkDeleteForm`을 통해 자동으로 토스트를 사용한다.
- CSV 가져오기는 파일 선택 안내 → 읽기 시작 → 적용 완료/실패 순서로 갱신한다.
- 테스트 시나리오 그룹 일괄 실행은 버튼 클릭 즉시 그룹명을 포함한 준비 토스트를 표시하고, 실제 실행 생성 후 건수 포함 완료 토스트로 갱신한다.
- 배치 실행 관리의 실행·일시정지·재개·취소도 같은 공통 토스트 계약을 사용한다.
- HITL 통합 리포트·JSON, 현재 증적 ZIP·개별 증적·Evidence Package ZIP 다운로드에 시작·완료·실패 토스트를 적용했다.

## 4. 수용 계약

- 대량·다운로드·CSV 작업은 네트워크 응답을 기다리기 전에 사용자의 클릭을 접수했다는 토스트를 먼저 표시한다.
- 준비 단계와 실제 실행을 구분한다. 계정 선택 전에는 `일괄 실행 요청·계정 확인`, Run 생성 후에는 `실행 시작`으로 표시한다.
- 시작 알림을 완료 성공으로 표현하지 않는다.
- 같은 작업의 완료·실패는 새 알림을 무한히 쌓지 않고 같은 ID로 갱신한다.
- 토스트는 앱 공통 호스트를 사용하며 화면별로 별도 위치·스타일을 만들지 않는다.
