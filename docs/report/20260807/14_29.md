## 1. 이번 단계에서 한 일

- HITL 실행 리포트에 노출되던 `criterion:*`, `backend_response` 같은 내부 누락 코드를 사용자 언어로 변환했다.
- 원래 코드는 JSON Structured Output에 감사·추적용으로 유지하고, UI와 다운로드 HTML에는 확인 대상·확인 방법만 표시한다.
- `run-report/v1`의 증적 계약에 파일별 라벨·경로·크기·마스킹·SHA-256·단계를 포함했다.
- HTML 다운로드를 `실행 리포트 → 기술 검증 → 증적 패키지` 단일 문서로 확장했다.
- 증적 패키지의 대표 A 화면·입력 완료·B 결과 화면을 HTML data URI로 포함하고, 전체 Artifact 목록도 함께 렌더링한다.
- 시나리오 일괄 실행 직후 각 행을 `실행 대기`로 초기화하고 SSE의 `progressPercent`·`currentStepId`·결과를 정적 실행 이력보다 우선 표시한다.
- 행별로 대기·실행 중·정상 관측·확인 필요·검토 대기의 상태와 진행 막대를 표시한다.
- SSE 오류 시 연결을 즉시 닫지 않고 EventSource의 기본 재연결을 유지하며, 복구 중에도 마지막 행 상태를 보존한다.
- 시나리오를 선택하지 않은 상세 영역은 중앙 대형 안내와 방향 아이콘으로 선택 행동을 명확히 했다.

## 4. 수용 계약

- 원시 누락 코드는 감사 JSON에서만 유지하며 사용자 화면·HTML에는 노출하지 않는다.
- `리포트 다운로드` 한 번으로 실행 리포트·기술 검증·증적 패키지 전체를 열람할 수 있어야 한다.
- 일괄 실행 요청 직후 각 대상 시나리오는 `실행 대기`로 보이며, SSE 수신마다 해당 행의 진행률과 현재 단계가 변한다.
- 종료 결과가 아직 기술 성공으로 분류되지 않았더라도 `관측 불가`로 오해시키지 않고 `실행 완료 · 검토 대기`로 구분한다.
- Complete는 HITL Pass가 아니며 정상 관측·확인 필요·검토 대기는 모두 기술 관측 상태다.
