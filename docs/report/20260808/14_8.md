# Phase 14 · 실행환경 데이터 변경 정책과 캐릭터 안내

## 요청 배경

QA_AUTO의 안전 차단이 대상 개발 애플리케이션 결함처럼 보이면 고객은 실제 업무 테스트 결과를
신뢰하기 어렵다. 프로젝트 생성 시 테스트 환경의 데이터 변경 허용 여부를 한 번 정하고,
실행과 예약 실행이 자동 상속하도록 개선했다.

## 구현

- `ExecutionEnvironment` 생성·수정·응답 계약에 `dataMutationAllowed`를 추가했다.
- Browser Run은 1회 승인보다 환경 정책을 먼저 확인하고, 허용 출처를 `runPolicy.source`에 기록한다.
- Run Preview가 환경 허용 여부를 노출해 허용 환경에서는 중복 승인 팝업 없이 업무 단계를 실행한다.
- 스케줄 실행도 환경 정책을 상속한다.
- 프로젝트 실행환경 단계의 계정 입력 아래에 `데이터 변경 허용` 선택란과 우측 캐릭터 설명을 추가했다.
- 공통 작업 알림과 주요 팝업·drawer·장시간 생성 화면에 캐릭터와 짧은 상황 설명을 추가했다.

## 검증

- Backend: 환경 CRUD·Run 정책 상속·계정·스케줄 테스트 12건 PASS.
- Frontend: Next.js production build PASS.
- 안전 기본값은 `false`이며 테스트 전용·초기화 가능한 환경에서만 사용하도록 화면과 문서에 명시했다.

## 후속 시연 원칙

기존 `확인 필요` 정책 차단 Run 대신 `dataMutationAllowed=true`인 깨끗한 데모 프로젝트에서 실제
입금을 한 번 실행한다. 영상은 변경 전후 잔액, 성공 안내, 거래 내역, 실행 증적, AI 요약,
리포트 도넛과 증적까지 같은 성공 Run ID로 이어서 보여준다.
