## 1. 이번 단계에서 한 일

사용자가 제시한 3개 트랙(좌측 메뉴 축소 · 상세 화면 정보 다이어트 · **잘못된 성공 판정 결함**)을 처리했다.

1. **좌측 메뉴 1depth 축소**
   14_1에서 붙였던 `테스트 시나리오` 하위 그룹 트리를 걷어냈다. `nav.ts`의 `dynamicChildren`·`NavChild` 계약과
   `AsideNav`의 트리 상태·`scenario-sets` 조회·펼침 토글·관련 CSS를 함께 제거했다.
   그룹 선택은 사용자가 만족한다고 밝힌 `/scenarios` 그룹 화면(2-pane)에서만 한다.
2. **시나리오 상세 3탭 재구성 (정보 다이어트)**
   상세 패널을 `[화면 구성 확인] [실행 흐름] [예상 테스트 결과]` 3탭으로 나누고, 탭마다 전용 아이콘·부제목을 붙였다.
   - 화면 구성 확인 — `이 테스트가 확인하는 것`(번호 목록) + `확인 대상`(대상 화면·확인 방식·수행 단계 + 확인 항목 칩)
   - 실행 흐름 — 단계 카드 + 단계별 스크린샷 (상세 헤더와 겹치던 요약·안내문 중복 제거)
   - 예상 테스트 결과 — `성공으로 보려면 / 실패로 봐야 하면` 2색 카드 + 실행 콘솔
   개발자용 정보(케이스 ID·시나리오 ID·단계 정의·selector·RUN/commit/버전·snapshot 수·INPUT 출처·원본 JSON)는
   지우지 않고 **접이식 `기술 상세`** 로 내렸다. 실행 콘솔의 단계 표기도 `S1` 같은 식별자에서 순번으로 바꿨다.
   실행 산출물 요약문에 남아 있던 `기술 실행 관측 완료 · 기술 상태=…` 표기는 화면에서만 담당자 문장으로 옮긴다
   (`humanizeObservation`) — 증적 원문은 그대로 둔다.
3. **세션 선행조건 · 기대결과 판정 지침 신설 (D-015)**
   사용자가 보고한 결함: **로그인 없이 `/logout`만 열어 서버가 거부(405 Allowlist methods)했는데도
   「Endpoint에 접근했다」는 이유로 성공 플래그와 증적이 남았다.**
   이번 회차에서는 코드로 우회 수정하지 않고, 플랫폼 개발자가 구현 근거로 쓸 **시스템 프롬프트·SKILL 계약·문서 지침**을 만들었다.
   - 신규 프롬프트 2종 — 세션 선행조건 보강(로그인 필수 판별 · 선행 로그인 단계 · `sessionPolicy` 4값 · 판정 기준),
     기대결과 대조 판정(`expected_met|expected_not_met|undetermined` + 항목별 사유 · `blockingIssues` · `coverageNote`)
   - 계정은 값이 아니라 참조로만 — `environment.loginId` / `environment.loginSecret`. 비밀번호 생성·출력·복원 금지
   - 인증 실패 신호(401·403·405·Allowlist·로그인 화면 회귀·`sessionEstablished:false`)는 실패로 관측하고
     `suggestedFix`에 **선행 로그인 추가**를 남긴다
   - 도달·무예외·스크린샷 존재를 성공 근거로 쓰지 못하게 프롬프트·SKILL·문서·Cursor Rule 4계층에 못 박았다

## 5. 핵심 근거

- 사용자 지시(이번 세션): 좌측은 1depth만, 상세는 `[화면구성확인][실행흐름][예상테스트결과]`를 타이포·아이콘으로 시각화하고
  기술 코드·개발자 정보는 화면에서 빼되 백데이터는 유지, 그리고 **「위 개선안은 코드로 푸는 것이 아니다 — 시스템 프롬프트
  고도화 지침으로 적용하라」**. 이에 따라 판정 로직을 임의 구현하지 않고 프롬프트·SKILL·문서·Rule 계층에 지침으로 남겼다.
- 결함 근거: 사용자 보고한 로그아웃 실행 관측(로그인 미수행 · `/logout` 직접 접근 · Allowlist methods 오류 · 그럼에도 성공 플래그·증적).
  현재 실행 요약문 근거는 `backend/app/skills/browser_execute/script/execute_run.py`의 `observationSummary`(`기술 실행 관측 완료`)다.
- 세션 정책 4값(`no_auth`·`login_then_reuse`·`reuse_existing_session`·`fresh_login_required`)과 계정 참조 방식은
  기존 보안 Guardrail(Secret·Token 미저장 · 합성/마스킹 데이터)과 `connection` 계약에 맞춰 정의했다.
- 지침 회귀 근거: `backend/tests/test_session_verdict_guidance.py` (프롬프트 존재 · 정책 값 · 도달=성공 금지 문구 · SKILL 계약 참조)
