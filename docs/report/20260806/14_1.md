## 1. 이번 단계에서 한 일

사용자가 제시한 Console UX 3개 트랙(대시보드 · 좌측 메뉴 · 테스트 시나리오 화면)을 구현했다.

1. **대시보드 — 내 프로젝트 즉시 식별·진입**
   히어로 안내 문구(`안녕하세요!` 이하 3줄)를 지우고 `내 프로젝트 캐러셀 + 다음에 할 일 | 빠른 작업` 3영역으로 재구성했다.
   프로젝트 타일은 이름 · `PRJ-…` 식별자 · 연결 저장소 수 · 시나리오 건수 · 최근 실행 시각만 실제 응답 필드로 채우고,
   없으면 `—`로 남긴다. 최근 순서는 `max(run.createdAt, scenario.createdAt)` → 없으면 `project.createdAt` 규칙으로 계산한다(추정 없음).
   첫 타일은 `최근 작업` 배지로 강조하고 `‹ ›`로 페이지를 넘긴다. 타일 클릭 → `/analysis?projectId={id}`.
   여정 5단(프로젝트·저장소·시나리오생성·시나리오목록·테스트실행)은 `Project.journey` 그대로 점 5개로 표시한다.
2. **좌측 메뉴 개편 — `/flow` → `/scenarios` 격상 통합**
   중복이던 구 `테스트 시나리오` 메뉴를 없애고 구 `플로우`를 `테스트 시나리오(/scenarios)`로 격상했다.
   `/flow`는 `setId`·`scenarioId`·`graphId`·`serviceId` 쿼리를 보존해 리다이렉트한다.
   `AsideNav`를 분리해 `GET /api/console/scenario-sets` 기준으로 하위 `테스트 시나리오 그룹` 트리를 접기/펼치기로 렌더한다.
   같은 저장소 이름이 반복돼 구분이 어려웠던 문제는 라벨에 생성일(MM-DD)·시나리오 건수를 붙여 해소했고,
   6건을 넘으면 `전체 보기`로 넘긴다.
3. **그룹 화면 — 목록 유지 + 우측 슬라이드 상세**
   `setId` 단계를 2-pane으로 바꿔 시나리오를 골라도 좌측 목록이 사라지지 않게 했다(무슨 시나리오가 있었는지 잃지 않도록).
   구 `시나리오 상세·재실행` 버튼의 `/scenarios/{id}` 포워딩을 없애고, 상세 본문을 `ScenarioDetailPanel`로 추출해
   우측에서 `anim-slide-left`로 그 자리에 렌더한다. 일괄 실행 · 종료 · 삭제는 그룹 단계 푸터로 이관하고 `ScenarioTable`은 제거했다.
4. **시나리오 단위 의존관계 그래프**
   `GET /api/scenarios/{id}/interaction-graph`를 신설했다. 부분집합은 결정론 규칙만 사용한다 —
   시나리오 DSL의 `steps[].evidenceRefs`(`graph:<nodeId>`)·`evidenceIndex[].nodeId`를 seed로 두고
   seed ∪ 1-hop 이웃 노드, 양 끝이 남은 edge만 유지한다. seed가 없으면 노드 없이 `missing_data`를 알린다.
   `FlowCanvas`는 scoped 모드에서 제목을 `{시나리오명} 시나리오 의존관계 그래프`로 쓰고,
   `그래프 ID` 셀렉트를 **테스트 시나리오 셀렉트**로 바꾸며, 부분 그래프에서는 `새 연결 추가`를 막고 이유를 적는다.
