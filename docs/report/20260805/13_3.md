## 1. 이번 단계에서 한 일

사용자 지적 2건을 데이터·문서 근거로 확인했다.

**(1) Variables (Input) / Response (Output) 공란**

- 사용자가 선택한 노드는 `node-screen-logout`이었고, 분석 결과의 `attributes.inputs`가 `[]`였다.
  BoA `/logout`은 리다이렉트 라우트로 입력 컨트롤이 없어 값 자체가 없는 것이 맞다.
- 다만 실제 결함이 함께 있었다.
  - `compose_graph`가 Backend 분석의 `pathParams`·`statusCandidates`·`responseDto`·`serviceCalls`,
    DTO `fields`를 노드 attributes로 옮기지 않아 **BE API·Request DTO 노드는 근거가 있어도 항상 `{}`** 였다.
  - 인스펙터가 값 없음을 전부 `{}`로만 표시해 「없는 게 정상」과 「미관측」과 「구현 누락」이 구분되지 않았다.
- 조치: attributes 전달 추가 + 인스펙터를 3상태(`observed` / `candidate` / `missing`)로 표시.
  값은 추정하지 않고 필드 키만 노출하며 값은 `null`로 남긴다.

**(2) A→C 재배선이 고정 버튼인 이유**

- `docs/`에 유연한 조건 편집(끊기·연결) 요구는 **기록이 없다**.
- 유일한 근거는 `docs/report/20260805/10_25.md` 14행 —
  Phase 10 회차 25 「스코어카드 95%」 갭 채우기 항목 `FLOW: 엣지 A→C 재배선`.
  스코어카드 한 줄을 충족하는 최소 구현(대상 노드 select + PATCH)으로 끝냈고,
  상호작용 모델은 별도 설계 없이 결정됐다. 사용자 의도와 다른 지점이다.
- 현재 능력 범위:
  - Backend `rewire_edge`는 이미 `condition` 변경과 `(from, oldTo)` 매칭을 지원한다.
  - **엣지 끊기(삭제)·새 엣지 생성 API는 없다.** 캔버스 드래그 연결도 없다.
- 사용자 선택(패널 편집 · 프리셋+자유입력 조건)에 따라 유연 편집을 구현했다.

**(3) 연결 편집 구현 (사용자 선택 반영)**

- 연결선의 **조건 pill을 클릭**하면 편집 패널이 열린다. 대상 노드·연결 종류·조건을 각각 바꾸고,
  **연결 끊기**·**새 연결 추가**를 할 수 있다.
- 조건은 Backend가 내려주는 프리셋(`happy_path`·`validation_error`·`auth_required`·
  `not_found`·`server_error`·`empty_result`) + 자유 입력(datalist)이다. 비우면 조건 없음.
- 사람이 만든/편집한 연결은 `editedBy: human`으로 저장하고 캔버스에서 **점선**으로 그린다.
  수동 추가 연결의 confidence는 **0.5** — 코드 근거가 없으므로 unresolved 등급(<0.70)을 유지한다.
- 발견·수정: 선(1.5px)이 노드 카드에 가려 클릭이 사실상 불가능했다 (E2E 240s 타임아웃으로 드러남).
  투명 14px 히트 영역을 두고, 조건 pill을 카드 위 레이어로 올려 항상 도달 가능하게 했다.
